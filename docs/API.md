# API contract

The authoritative current schema is [openapi.json](openapi.json), generated by `clinic-voice export-openapi`. Base path `/v1/tools`; all tools require `Authorization: Bearer cvt_<credential id>.<secret>`, issued by `clinic-voice credential issue`. The server resolves clinic identity from the active credential record. Malformed, unknown, wrong-secret, expired and revoked credentials all return the same 401 with `WWW-Authenticate: Bearer`. Unknown body fields, including `clinic_id` or patient fields, are rejected.

Slot query: `doctor_id` UUID, `service_id` UUID, `day` ISO date. Valid dates are today through the clinic's `horizon_days` (default 90) ahead in clinic timezone. Inactive doctors or services return 404 for slot lookup and reservation. Slots start on a duration grid from each configured opening time; end must fit inside the window. Past slots and local overlapping holds are excluded. Calendar external conflicts, holidays, buffers, and time-of-day filters are not implemented.

Reservation: `doctor_id`, `service_id`, offset-aware `starts_at`. Require `Idempotency-Key` (8–128 characters, letters/digits/dot/underscore/colon/hyphen). Same key/body replays appointment; same key/different body returns 409. Offset-equivalent timestamps hash identically. Invalid/missing authentication returns 401; unknown tenant catalog objects 404; validation 422; slot conflict 409. Database errors return a generic 503 without SQL details; retry the same logical action and idempotency key after recovery.

Response includes appointment ID, `pending_sync`, start/end, and cautious spoken text. This contract intentionally differs from the DOCX's `book-slot` request: no caller-supplied clinic phone, free-form doctor lookup, patient name/phone, or unconditional `CONFIRMED`. The future Bolna gateway must adapt trusted context into this API and complete identity verification before patient-specific changes.

## Staff authentication

Staff endpoints take `Authorization: Bearer cvs_<session id>.<secret>`. Tool credentials (`cvt_`) and staff sessions (`cvs_`) are not interchangeable. The staff user's clinic is the tenant for every staff call; bodies cannot carry `clinic_id`. Login failures for unknown, disabled, locked or wrong-password accounts return the same 401. Five consecutive failures lock an account for 15 minutes. Roles: `owner` manages staff; `admin` can list staff and manage clinic configuration; `viewer` is read-only. Role and disable changes apply on the next request. Passwords are 12–256 characters; validation errors never echo them. Staff emails are globally unique, so creating an email already used by another clinic returns 409.

## Clinic configuration

`/v1/admin/*` uses staff sessions; the clinic always comes from the session and bodies carrying `clinic_id` (or any unknown field) return 422. GET is open to owner, admin and viewer; mutations need owner or admin (viewer gets 403). Any doctor, service or hours id that is unknown or belongs to another clinic returns 404 identically. PATCH bodies must contain at least one field and no nulls. `timezone` must be a canonical IANA key known to the server (e.g. `Asia/Kolkata`); `local`, empty or unknown names return 422. Hours are a list of `{weekday 0-6 (Monday=0), opens "HH:MM", closes "HH:MM"}`, at most 50 entries; `opens` must precede `closes` and windows on one weekday may touch but not overlap. PUT replaces the whole set in one transaction (an empty list makes the doctor unbookable) and takes the same doctor row lock as reservations. Mutations write `audit_events` (`clinic.updated`, `doctor.created`, `doctor.updated`, `service.created`, `service.updated`, `hours.replaced`) with ids only. `lead_time_minutes` and `buffer_after_minutes` are stored but not yet applied to slot computation.

Cancel, reschedule, webhooks, schedule exceptions, credential administration over HTTP, OAuth, provisioning, and provider administration endpoints are backlog items. No live Bolna tool payload is shipped as provider-validated JSON.
